# OFM-API-SIGNATURE-409 — عدم نمایش کامل نمونه‌امضاهای کاربر

- **سامانه:** برید سامانه / Fonix / OFM
- **دسته:** خطاهای API، امضای کاربر، AngularJS
- **تاریخ ثبت:** ۱۴۰۵/۰۸/۱۸
- **وضعیت گزارش‌شده:** رفع‌شده و تأییدشده توسط کاربر
- **سطح قطعیت علت:** علت فنی قطعی از روی لاگ موجود اثبات نشده است.

## شرح مشکل
هنگام کلیک روی کامپوننت امضا، سامانه باید همه نمونه‌امضاهای ثبت‌شده کاربر را برای انتخاب نمایش دهد. در برخی شرایط تعدادی از تصاویر به‌طور کامل بارگذاری نمی‌شوند. تصویر مرجع ارائه‌شده توسط گزارش‌دهنده، وضعیت سالم پنجره با **چهار نمونه‌امضا** را نشان می‌دهد.

## لاگ‌های مرتبط
```text
GET /Fonix/OFM/api/user/GetUserSignature?index=2&Id=0 409 (Conflict)
GET /Fonix/OFM/api/user/GetUserSignature?index=3&Id=0 409 (Conflict)
GET /Fonix/OFM/api/user/GetUserSignature?index=4&Id=0 409 (Conflict)

TypeError: Cannot read properties of undefined (reading 'find')
at ngFormBuilder-complete.min.js:127:11791

Possibly unhandled rejection: undefined
Possibly unhandled rejection: {}
```

## تحلیل
- پاسخ HTTP 409 برای چند درخواست متوالی دریافت امضا مشاهده شده است.
- پارامتر `Id=0` نیازمند بررسی معنای دقیق در پیاده‌سازی API است؛ نمی‌توان صرفاً آن را شناسه نامعتبر دانست.
- خطای `find` می‌تواند ناشی از پردازش داده تعریف‌نشده باشد، اما رابطه علّی آن با پاسخ 409 هنوز قطعی نیست.
- کندی شبکه، تأخیر سرویس، محدودیت فاصله درخواست‌ها و مدیریت‌نشدن پاسخ ناموفق، عوامل احتمالی هستند.

## تنظیمات قابل بررسی
مسیر: **مدیریت کاربران ← انتخاب/ویرایش کاربر ← تنظیمات امنیتی ← تنظیم فاصله بین درخواست‌ها**

- **حداقل زمان درخواست (GET)** — اولویت بررسی، زیرا `GetUserSignature` از نوع GET است.
- **حداقل زمان درخواست (POST)** — برای کنترل تنظیمات مرتبط بررسی شود.
- واحد تنظیمات: میلی‌ثانیه.

مقدار مشخص یا استانداردی بدون بررسی پیکربندی و سیاست امنیتی سامانه توصیه نمی‌شود.

## روش عیب‌یابی و رفع اشکال
1. مقدار فعلی GET و POST را ثبت کنید.
2. در Developer Tools، بخش Network و گزینه Preserve log را فعال کنید.
3. پنجره انتخاب امضا را باز کرده و درخواست‌های `GetUserSignature` و پاسخ آن‌ها را بررسی کنید.
4. وضعیت ثبت نمونه‌امضاهای کاربر و تست با کاربر دیگر را بررسی کنید.
5. در صورت نیاز، با هماهنگی مدیر سامانه، مقدار حداقل فاصله درخواست GET را به‌صورت کنترل‌شده آزمایش کنید؛ از کاهش دائمی محدودیت امنیتی بدون تأیید خودداری کنید.
6. نتیجه قبل و بعد را از نظر تعداد تصاویر بارگذاری‌شده و وضعیت HTTP مقایسه کنید.
7. اگر مشکل باقی ماند، Response سرویس، Event Viewer سرور و کد پردازش پاسخ در کامپوننت امضا بررسی شود.

## نتیجه و وضعیت
گزارش‌دهنده وضعیت پرونده را **رفع‌شده و تأییدشده** اعلام کرده است. با این حال، مقدار دقیق تنظیمات تغییرکرده و شواهد اثبات علت ریشه‌ای ارائه نشده‌اند؛ بنابراین **تنظیم فاصله درخواست‌ها به‌عنوان عامل محتمل/راهکار بررسی‌شده** ثبت می‌شود، نه علت قطعی تأییدشده.

## پاسخ پیشنهادی پشتیبانی
در صورت عدم نمایش کامل نمونه‌امضاها، ابتدا از مسیر مدیریت کاربران، تنظیمات امنیتی کاربر و مقادیر «حداقل زمان درخواست (GET)» و «حداقل زمان درخواست (POST)» بررسی شوند. به‌دلیل GET بودن سرویس دریافت امضا، بررسی تنظیم GET اولویت دارد. پس از هر تغییر کنترل‌شده، عملکرد نمایش همه امضاها و پاسخ‌های شبکه مجدداً آزمایش شود.
